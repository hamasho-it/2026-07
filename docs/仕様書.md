# 「カサピタ」アプリ 画面・システム仕様書（仮仕様版）

## 1. アプリの名前と目的

- **アプリ名**：カサピタ
- **目的**：
  飲食店の卓上NFCタグと空間Bluetoothビーコンを活用し、退店時のスマートフォン通知によって傘の置き忘れを自動防止するシステムを提供します。
  ユーザーの置き忘れストレス解消と飲食店の傘管理負担軽減を実現し、街の放置傘（プラスチックゴミ）削減および「使い捨て文化から愛着文化へ」の意識変容を目指します。
- **ターゲットユーザー**：
  - **外勤ビジネスパーソン・ノマドワーカー（20代〜50代）**：外出先カフェでの仕事中に安心を提供。
  - **雨の日にカフェや外食を楽しむ一般ユーザー（大学生・社会人）**：お気に入りのマイ傘を守る安心感を訴求。
  - **雨の日の観光客・インバウンド（訪日外国人）**：慣れない土地での置き傘防止および「雨の日安心スポット」案内。

## 7. 守る条件

1. **技術構成**:
   - HTML・CSS・JavaScript（フロントエンドのみ）で作成し、データベースおよびバックエンドログイン機能は実装しない。
   - スタイルは `./style.css`、共通処理スクリプトは `./script.js` のそれぞれ1ファイルに統一し、全画面から相対パスで読み込む。
2. **ファイル構造・パス指定**:
   - 各画面を独立したHTMLファイルとして分割する（最初の画面は `./index.html`）。
   - ファイル名・画像フォルダ名は半角英数字のみを使用し、リンクやリソース参照はすべて `./` から始まる相対パスで記述する。
3. **デザイン・表示仕様**:
   - モバイル端末（スマートフォン）に最適化したレスポンシブなビューポートサイズで設計する。
   - 配色基調は白・黒・灰色のモノトーンとし、仮レイアウトとしてシンプルに仕上げる。
   - ワイヤーフレーム上のカッコ書き `（確定する）` のカッコは除外してテキストを表示する。
   - 画面遷移図に書かれている案内メッセージ・完了通知テキストは、該当する画面内に明記して表示する。
4. **機能制限・非実在データの徹底**:
   - 画面遷移図およびワイヤーフレームに存在しない機能や画面は追加しない。
   - 仮データ（人名・店名・地名・電話番号・メールアドレス）はすべて「サンプル」「000-0000-0000」等の架空表現を使用し、実在する情報を一切含まない。

## 8. 確認したいこと（図にない・決まっていないこと）

1. **下部ナビゲーションアイコンの遷移先割り当て**:
   - マップ画面やチェックイン画面などの下部に配置されている4つの丸型ナビゲーションアイコンについて、画面遷移図上に明示的な矢印がないアイコンがあるため、本仕様書では「マップ」「チェックイン」「安心スポット」「マイページ」の主要4画面への切り替えボタンとして暫定定義しています。正式なアイコンデザインおよび割り当てのご確認をお願いします。
2. **退店通知の「持っている」選択後の詳細挙動**:
   - 画面遷移図上では「持っている → 案内が終了したら自動的に戻る」と記載されています。本仕様書では「持っている」ボタンタップ後に直接「チェックイン画面（`./checkin.html`）」へ復帰させる仮仕様としていますが、アニメーションや数秒の完了メッセージ挟み込みの要否をご確認ください。
3. **雨の日安心スポットからのルート案内画面レイアウト**:
   - 「ルート案内開始画面」および「案内終了画面」は画面遷移図上に定義されていますが、ワイヤーフレーム画像には単独のレイアウト図が含まれていません。本仕様書ではマップ画面ベースのオーバーレイ/専用表示画面（`./route_guidance.html`）として作成する仮仕様としています。
4. **「戻るマップルート画面」到着後の自動画面リダイレクト**:
   - 戻るマップルート画面から目的地到着後に「目的地到着後画面（`./destination_arrival.html`）」を表示し、さらに「チェックイン画面」へ戻る遷移の流れについて、自動タイマー遷移か画面タップ遷移かの動作仕様をご確認ください。
